CONNECT to …

Your databases, as they are.

Five server protocols, two databases that live in a file, and three relatives of PostgreSQL the app recognises on its own. Each dialect keeps its rules: quoting, script separators, plans, transactions.

FROM eleven kinds of database

What it speaks.

PostgreSQL

Dollar quoting in scripts, EXPLAIN as JSON, sessions that are read only on the server, roles with SCRAM.

pg_dump · pg_restore · psql

MySQL

DELIMITER in scripts, backticks for names, users with hosts. One driver for MySQL and MariaDB.

mysqldump · mysql

MariaDB

Recognised by what the server says about itself. Its own tools (mariadb-dump, mariadb) are found as well.

mariadb-dump · mariadb

SQL Server

GO splits batches, names in brackets, plans as XML, logins and users.

simple SQL export

SQLite

A file on your disk. And a demo database in memory, there from the first start, to try everything without a server.

a copy of the file

CockroachDB · TimescaleDB · YugabyteDB

They speak PostgreSQL’s protocol. The app finds out who answers and adapts: cancel, transaction state, catalog.

connect as PostgreSQL

Oracle

A driver in pure Rust: no Instant Client to install. PL/SQL blocks end at a line with /, dates are bound as dates. Run, browse, details with DDL, edit rows, search.

plans, monitor, rights: not yet

ClickHouse

Over its HTTP interface, to read and analyse: run, cancel, browse, filter, search. It has no transactions and no unique keys, so rows are not edited in the grid.

read and analyse

DuckDB

Built in. A file or :memory:, and SELECT * FROM 'sales.parquet' just works. Nothing is downloaded: extensions are never loaded on their own.

Parquet · CSV · JSON

The drivers are tested against real servers of every kind, started in containers; SQLite and DuckDB run inside the tests.

USING a profile

Connecting.

A connection is a profile: where, as whom, how secured. Profiles live in folders, carry a colour that marks their tabs, and never hold a secret.

Passwords in the keychain

Not in a file. Not in an export.

After a login that worked, the password goes to the keychain of your system: Keychain on macOS, Credential Manager on Windows, the Secret Service on Linux. The file with the profiles can be read by anyone without telling them anything.

SSH tunnel

For the database that is not on the internet. Most are not.

Sign in with the SSH agent, a key or a password. The host key is checked against your known_hosts; an unknown key asks you to confirm its fingerprint, a changed key is refused. ~/.ssh/config is read for host names and users, and nothing in it is ever executed.

TLS, the way your server wants it

From “off” to “verify everything”.

Choose the mode per connection, bring your own certificate authority, and a client certificate if the server asks for one. The same settings are handed to the backup tools, so a dump runs as securely as the session.

postgres://user@host/db

From a URL

Paste a connection URL and the profile is filled in. A password in the URL goes to the keychain, not into the profile.

DBeaver · DataGrip

REVOKE the accident

Protection for production.

Every connection has a level. The backend classifies each statement as reading, writing, DDL or dangerous and decides; the window only shows the question.

free

Free

Only what is dangerous asks first: a DELETE or UPDATE without WHERE, a DROP, a TRUNCATE.

ask

Ask

Everything but reading asks first. For what is dangerous you type the name of the connection.

read only

Read only

Nothing but reading runs. Editing, importing, copying into it and restoring are refused in the backend.

The same check guards everything that writes: the editor, the grid, structure changes, import, copying tables, test data, rights, ending a session.
