# Design 035l: IBM Db2

> Durchlauf von [Prompt 035](035-weitere-datenbanken.md) für **Db2 for Linux, UNIX and Windows**. Stand: umgesetzt
> am 12.11.2026 (ohne Freigabe-Halt; Marc am 12.11.2026: „Ja, ungeprüft“) – **nach dem Quelltext des Treibers
> und IBMs Dokumentation geschrieben, nie gegen einen Server gelaufen**: Das offizielle Abbild braucht einen
> privilegierten Container, den hier niemand erlaubt hat. Getestet ist, was ohne Server geht.

## Ergebnis in einem Satz

Db2 ist eine eigene `DbKind` zum **Lesen und Ausführen**: verbinden (auch über TLS und SSH-Tunnel), Anweisungen
ausführen und abbrechen, Baum, Details, Tabellen-Ansicht mit Filter, Suche. Jede Anweisung ist für sich
abgeschlossen (Auto-Commit); Zeilen im Gitter ändern, Import und Kopieren gibt es dort noch nicht.

## Entscheidungen

| # | Entscheidung | Warum |
|---|---|---|
| E1 | Treiber **`justybase-db2`** (`=0.1.0-alpha.3`, MIT): DRDA in reinem Rust, asynchron auf unserer eigenen tokio-Laufzeit | `ibm_db` braucht IBMs CLI-Bibliothek (C, je System zu installieren); die Crate `db2` ist ein leerer Platzhalter. Der Treiber ist eine **Alpha eines einzelnen Autors** – darum fest auf die gelesene Version gesetzt (`#![forbid(unsafe_code)]`, eigene Abhängigkeiten: `ring`, `tokio-rustls`, `des`, `crypto-bigint`, `zeroize`) |
| E2 | Die Crate verlangt **Rust ≥ 1.98.1**: `rust-version` des Projekts steigt von 1.93 dorthin | sonst baut sie nicht; CI und Release nehmen ohnehin „stable“ |
| E3 | **Auto-Commit, keine Transaktion des Tabs**: Jede Anweisung wird abgeschlossen – vom Treiber, und wo er es nicht tut (ein Cursor ohne gebundene Werte), von `db2::one` selbst: Commit nach dem Ende, Rollback nach einem Fehler. `edits_rows` ist falsch (kein Bearbeiten, kein Import, kein Kopieren), `TxState` immer „keine“ | Eine Transaktion offen zu halten hieße, dem ungeprüften Treiber Daten anzuvertrauen, die er verlieren könnte. Erst lesen, dann – gegen einen echten Server geprüft – schreiben |
| E4 | Werte reisen **gebunden** (`?`). Der Treiber würde einen Wert an den Typ des Platzes anpassen und dabei ändern (`1.5` → `1` für `INTEGER`, jede Zahl ≠ 0 → wahr, ein Zeitstempel → sein Datum, ein Text → die Bytes seiner Hex-Ziffern); `db2::fits` liest darum erst die Beschreibung der Plätze (`prepare`) und **lehnt ab**, was nicht passt | nie runden (Arbeitsweise) |
| E5 | Was eine Anweisung gibt, sagt ihr erstes Wort: `SELECT`/`WITH`/`VALUES` → Zeilen als Strom; `CALL` → erstes Ergebnis der Prozedur, ganz gelesen; sonst Zahl der geänderten Zeilen | so trennt es auch der Treiber |
| E6 | **Abbruch** über eine zweite Verbindung (`SQLINTR`, `interrupt_handle`), durch einen Tunnel angekündigt. Antwortet der Server nicht, gilt die Verbindung als verloren | wie Firebird |
| E7 | Ein Ergebnis, das vor seinem Ende verlassen wird (Grenze erreicht), liest der Treiber höchstens 3 s zu Ende – danach **kostet es die Verbindung** | DRDA kennt im Treiber kein frühes Schließen eines Cursors; die Tabellen-Ansicht setzt ohnehin `FETCH FIRST` |
| E8 | **TLS nur „verify“ oder aus**: Der Treiber prüft Zertifikat und Namen immer. Mit TLS ist der Vorgabe-Port **50001** (der Treiber nähme ihn für 50000 ohnehin, ungefragt – 50000 mit TLS wird darum abgelehnt). Durch einen SSH-Tunnel geht TLS nicht (der Name wäre der dieses Rechners) – abgelehnt mit Worten | kein ungeprüftes TLS vortäuschen |
| E9 | Katalog aus **`SYSCAT`** (`SCHEMATA`, `TABLES`, `COLUMNS`, `VIEWS`, `INDEXES`, `REFERENCES`, `ROUTINES`, `TRIGGERS`), der Name immer gebunden; Schemata von IBM (`SYS…`, `NULLID`, `SQLJ`) als System markiert | Standard von Db2 LUW |
| E10 | Dialekt: Namen in `"…"`, unquotiert nur in Großbuchstaben; „enthält“ über `LOCATE` (kein Muster, nichts zu maskieren); `FETCH FIRST n ROWS ONLY`; Binärwerte über `HEXTORAW`; ein Platzhalter ohne Spalte daneben bekommt seinen Typ (`CAST(? AS VARCHAR(…))`) | Db2 kennt einen Platzhalter ohne Typ nicht überall |
| E11 | Der Zerleger hält einen Block von SQL PL (`BEGIN … END`, Rumpf einer Routine oder eines Triggers) zusammen | sonst liefe ein halber Rumpf |
| E12 | Ein Assistent (MCP) bekommt dort keine Abfrage ausgeführt | Db2 hat keine Sitzung, die auf dem Server nur lesen darf |

## Was noch fehlt (bewusst)

- Transaktionen, Bearbeiten, Import, Testdaten, Kopieren; Plan, Monitor, Rechte, Struktur, Schema-Vergleich.
- Schlüssel und Indizes im Baum, Fremdschlüssel folgen, Beziehungen im ER-Diagramm (die Details eines Objekts
  zeigen Indizes und Fremdschlüssel schon); das DDL einer Tabelle (Db2 schreibt es nur über `db2look`).
- Routinen, Trigger, Sequenzen im Baum.
- Db2 for z/OS und Db2 for i (ihr Katalog heißt anders); Kerberos.
- Die Anmeldung schickt das Passwort so, wie der Server es verlangt – ohne TLS im schlimmsten Fall im Klartext
  (DRDA `SECMEC 3`, der Normalfall bei `AUTHENTICATION SERVER`). Über fremde Netze: TLS oder Tunnel.

## Nicht getestet

- **Alles gegen einen Server**: Verbinden, Anmelden, jede Katalogabfrage, wie Werte ankommen (Datum, Zeit,
  `DECFLOAT`, große Objekte), Abbruch, TLS. Der erste Lauf gegen ein echtes Db2 ist der eigentliche Test; die
  Katalogabfragen sind die wahrscheinlichste Stelle für einen Fehler.
- Das native Fenster.

## Tests

- `src-tauri/src/db/db2.rs` (7 Tests ohne Server): was gebunden wird und was abgelehnt (`fits`), Zellen aus
  Werten (beide Schreibungen eines Zeitstempels), erstes Wort, Typnamen, Profil (TLS-Modi, Zertifikate, Passwort
  in keinem Text der Konfiguration), Fehler in unseren Codes.
- `filter.rs` (Tabellen-Ansicht, freie Bedingung), `guard.rs` (`FINAL TABLE`, `NEXT VALUE`, kein Backslash),
  `mod.rs` (Flags), `import.rs` (`jdbc:db2://…`, DBeaver); im Fenster der Zerleger.

## Review

Ein zweiter Agent hat den Stand gegen den Quelltext des Treibers und IBMs Dokumentation gelesen (nur lesend):
33 Befunde. Behoben, mit Test, wo einer ohne Server möglich ist:

| # | Befund | Behoben durch |
|---|---|---|
| 1 | Ein `SELECT` ohne gebundene Werte wurde **nie abgeschlossen**: Der Treiber sendet den Commit nur hinter einem Cursor mit Werten. Sperren blieben, und was ein `SELECT … FROM FINAL TABLE (INSERT …)` schrieb, hing bis zur nächsten Anweisung | `db2::one` schließt selbst ab: Commit nach dem Ende des Cursors, Rollback nach Fehler oder Ablehnung |
| 2 | Wurde ein schreibendes `SELECT` vor seinem Ende verlassen, standen die Zeilen da, die Änderung aber rollte zurück | ein Fehler statt eines Ergebnisses, der das sagt; auch ein Fehler beim Zu-Ende-Lesen gilt als verlorene Verbindung |
| 3 | Die Suche auf dem Server scheiterte an `SUBSTR(text, 1, 4000)` (Db2 lehnt eine Länge über der des Textes ab) | `SUBSTRING(…, CODEUNITS32)`; `FETCH FIRST` statt `LIMIT` |
| 4 | Der Zerleger trennte `BEGIN ATOMIC IF … END IF; … END` | `ATOMIC`/`NOT` hinter `BEGIN` zählen nicht als Anweisung |
| 5 | `fits` übersah weitere stille Umwandlungen | Datum, Zeit, Zeitstempel nur in ihrer genauen Form; `DECFLOAT` nach Stellen; `REAL`/`DOUBLE` endlich und im Bereich; `BOOLEAN` nur 0/1; `GRAPHIC` nach Länge; kein Text an einem Platz für Bytes |
| 6 | Mit TLS verband der Treiber statt mit 50000 mit 50001, die Meldung nannte 50000 | Vorgabe mit TLS ist 50001, 50000 wird abgelehnt (Backend und Dialog), die Meldung nennt den echten Port |
| 7 | Fehler des Treibers ohne SQLCODE hießen „keine Verbindung“; ein Tabellenname mit „certificate“ galt als TLS-Fehler | Abbildung nach der Art des Fehlers; Zertifikatsdateien werden vorab geprüft |
| 8 | Ein großes Objekt über der Grenze kostete nach 30 s die Verbindung | der Treiber darf 10 min daran vorbeilesen; die Zelle sagt, was zu tun ist |
| 9 | `REAL` zeigte Ziffern, die der Server nie hatte (0.1 → 0.10000000149011612) | zurück auf die Zahl aus vier Bytes |
| 10 | Details lasen Spalten des Katalogs, die IBM abkündigt (`COLNAMES`, `FK_COLNAMES`) | `LISTAGG` über `SYSCAT.INDEXCOLUSE` und `KEYCOLUSE` |
| 11 | `EXPLAIN PLAN FOR …` galt als lesend, `ALTER TABLE … WITH EMPTY TABLE` nicht als gefährlich; geschachtelte Kommentare | schreibend, gefährlich; `/*` in einem Kommentar macht die Anweisung „nicht sicher lesend“ |
| 12 | Zerleger: geschachteltes `CASE … END END`, `AS ROW BEGIN`, `begin1`, `repeat(…)`, `--#SET TERMINATOR @` | behoben, je ein Fall (das geschachtelte `CASE` auch für Snowflake) |
| 13 | `… KEEP UPDATE LOCKS`, `ON COMMIT DELETE ROWS` galten als gefährlich, `OPTIMIZE FOR n ROWS` als DDL | nicht mehr |
| 14, 24 | Namen des Katalogs womöglich mit Leerzeichen aufgefüllt; `KEYSEQ` | `RTRIM` in allen Listen; `COALESCE(keyseq, 0) > 0` |
| 15, 18, 21, 22, 27, 31 | `TIMESTAMP(12)` gekürzt; „Db2 DB2 v11…“; `LIMIT`; Regex auf `FOR BIT DATA`; `USER`, `CURRENT_DATE` … als Namen; Zertifikat ohne TLS im Dialog | bleibt Text; Vorsilbe entfernt; `FETCH FIRST`; ausgenommen; gequotet; im Dialog gemeldet |

Offen geblieben (bewusst, oben oder hier benannt): `CALL` liest nur das erste Ergebnis und keine OUT-Parameter
(16); die Zahl der geänderten Zeilen bei DDL (19); das Passwort ohne TLS (20); `VARCHAR(spalte)` schreibt
Zahlen und Daten anders als das Gitter (23); `"DEFAULT"` ist ein CLOB (25); der Typname ohne `FOR BIT DATA`
und Längen großer Objekte (26); ein Binärwert über 32 672 Hex-Ziffern als `BX'…'` (28); Funktionen mit
Nebenwirkung, die der Schutz nicht kennt (`UTL_FILE`, `MQSEND`, Tabellenfunktionen mit `MODIFIES SQL DATA`, 29);
ein Handler mit `IF` ohne Klammern im Zerleger (30); `:name` an Stellen ohne Typ (33).
